# Roamflight 实现计划

本文件是逐项实施和验收的主清单。依据：[产品方向](PRODUCT.md)与[原项目源码审计](UPSTREAM_AUDIT.md)。
不把读过源码、写完代码、构建通过等同于完整交付；只有验收通过并提交，才能标记完成。

## 提交规则

- 每个编号对应一个可独立验收的增量；必要时拆成更小提交，不混入无关修改。
- 先实现最小完整流程，再补视觉细节；不在半成品状态下把功能写进“当前已支持”。
- 每次更新本清单，记录测试和提交；提交到 `daoleno/roamflight` 后检查 CI。
- 修改玩法、界面或渲染时检查桌面和手机；音频修改检查输出、静音和动态过渡。
- 可发布增量部署到 Pages 并复查公网。DNS、账号权限或外部数据许可单独记录，不能假装已完成。
- 不为了接近原作重新增加大量配置；玩家端保持经过设计的默认体验。

## 发布门槛

每项都应通过 `npm test`、`npm run format:check` 和 `npm run build:pages`。
界面/渲染改动至少检查 1440×900、390×844 和手机横屏。真实设备性能测量与
软件渲染浏览器检查分开记录，不用后者冒充手机性能结论。

本计划不会在一次提交中全部标记完成。每完成一项，在下方补充验收和提交记录。
